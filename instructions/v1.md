# AlphaEvolve Investment Lab

## Self-Improving Stock Investment Strategy System

### 1. Project Objective

Build a self-improving quantitative investment research system inspired by AlphaEvolve / OpenEvolve.

The goal is **not simply to predict whether a stock will go up or down tomorrow**.

The goal is to build a system that can continuously:

1. Generate investment strategies.
2. Mutate and improve existing strategies.
3. Backtest every strategy.
4. Evaluate strategies across multiple market regimes.
5. Eliminate weak or overfitted strategies.
6. Preserve strong and diverse strategies.
7. Track how the strategy population evolves over time.
8. Produce a daily evolution report.
9. Display the entire process through a web dashboard.
10. Eventually provide investment decision support for real-world investing.

The core research question is:

> **Which investment strategy works best under which market condition?**

The system should not search for one permanently “best” strategy.

Instead, it should gradually discover a portfolio of strategies and learn:

> Strategy × Market Regime → Historical Performance

# 8. Strategy Genome

The unit being evolved is the **investment strategy code**.

Every strategy must follow a standard interface.

For example:

```python
class Strategy:

    def generate_signal(self, data, features, regime):
        return position
```

Where:

```text
1.0 = 100% Long
0.5 = 50% Long
0.0 = Cash
-0.5 = 50% Short
-1.0 = 100% Short
```

For Phase One, long/cash strategies may be used first:

```text
1.0 = Long
0.0 = Cash
```

Shorting can be added later.


```python
    use_momentum()
```



# 13. Trade Expectancy

Explicitly calculate:

```text
Expectancy =
Win Rate × Average Win
-
Loss Rate × Average Loss
```

Win rate should never be treated as the primary indicator by itself.

A strategy with:

```text
70% win rate
```

may still lose money if losing trades are much larger than winning trades.

Therefore the dashboard should always show:

```text
Win Rate
Average Win
Average Loss
Payoff Ratio
Expectancy
Profit Factor
```

together.

# 15. Complexity Penalty

Evolution will naturally produce increasingly complicated rules.

Therefore calculate strategy complexity.

Possible measures:

```text

```

Add a complexity penalty to the fitness function.

Prefer:

> Simple + Robust

over:

> Complex + Slightly Higher Backtest Return

# 16. Overfitting Protection

This is mandatory.

Never allow the evolutionary system to repeatedly optimize directly against the final test period.

Divide data into:

```text
TRAIN
VALIDATION
HIDDEN TEST
```

Example structure:

```text
TRAIN
2012–2019

VALIDATION
2020–2022

HIDDEN TEST
2023 onward
```

Exact dates should be configurable.

The LLM and evolutionary search must never see hidden-test performance during mutation.

---

# 17. Walk-Forward Testing

Also implement walk-forward evaluation.

Example:

```text
Train 2012–2016 → Test 2017
Train 2013–2017 → Test 2018
Train 2014–2018 → Test 2019
Train 2015–2019 → Test 2020
Train 2016–2020 → Test 2021
...
```

Each strategy should therefore have:

```text
one training performance
multiple walk-forward performances
one validation performance
one hidden-test performance
```

The system should favor strategies whose results are stable across periods.

# 20. Meta Strategy / Strategy Router

Eventually the system should evolve beyond individual strategies.

The higher-level system should learn which strategy to use under each market regime.

Example:

```python
if regime == UPTREND:
    use_strategy("Momentum_V37")

elif regime == SIDEWAYS:
    use_strategy("MeanReversion_V19")

elif regime == HIGH_VOLATILITY:
    use_strategy("Breakout_V51")

elif regime == DOWNTREND:
    use_strategy("Defensive_V12")
```

This becomes the:

# Strategy Router

The long-term goal is therefore not:

> Find one best strategy.

The goal is:

> Find the best available strategy for the current market environment.

# 42. Main Fitness Philosophy

Do not use one simple fitness score such as:

```text
fitness = total_return
```

The system should optimize several dimensions.

For example:

```text
Return
Risk
Drawdown
Stability
Turnover
Complexity
Regime Robustness
```

A possible initial composite fitness:

```python
fitness = (
    0.25 * normalized_cagr
    + 0.20 * normalized_sharpe
    + 0.15 * normalized_sortino
    + 0.15 * normalized_calmar
    + 0.10 * robustness_score
    + 0.10 * regime_stability
    - 0.025 * turnover_penalty
    - 0.025 * complexity_penalty
)
```

Do not hard-code this permanently.

The weights must be configurable.

# 45. Product Philosophy

The final product is not simply a quantitative backtesting tool.

It is not simply an LLM agent.

It is not simply a trading dashboard.

It should become a:

# Self-Improving Investment Research Engine

The system continuously asks:

```text
What investment rules currently exist?

Which ones work?

Under what market conditions do they work?

Why did they work?

Can we modify them?

Can we combine them?

Can we make them more robust?

Can we reduce drawdown?

Can we improve risk-adjusted return?

Can we preserve different successful approaches?

Has the new strategy survived out-of-sample testing?
```

The final philosophy can be summarized as:

> **Do not ask AI to predict the stock.
> Ask AI to continuously evolve better ways of investing in the stock.**

And then:

> **Do not search for one universal best strategy.
> Discover which strategies work under which market regimes.**
